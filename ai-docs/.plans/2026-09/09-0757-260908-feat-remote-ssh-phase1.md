# Plan: 260908-feat-remote-ssh — Phase 1: ssh transport

## Relevant Ticket Contract

- Remote = ssh wrapper: a non-`local` `<dest>` runs `ssh <dest> <remote-bin> local --jsonl --inline-captures --expect-version <local version> <fwd opts> -f -`, feeds the (rewritten) sequence on stdin, reads remote JSONL from stdout, reprints it locally, writes captures/`qclip[f]` files locally under `--out` precedence (ticket Decisions; help-remote.txt HOW IT WORKS, help.txt DESTINATIONS `:830-864`).
- Forwarded options: always `--jsonl --inline-captures --expect-version <local version>`; `-q --delay --timeout -k --cap-on-error --request-perms` when given. Local-only: `--out --remote-bin`. `--check`/`--ir` never start ssh (already true today — they return before dest resolution).
- `--expect-version` mismatch: remote stderr `version mismatch: remote <x>, expected <y>`, exit 3, nothing else printed (already implemented for the local process itself in `cmd/gotto-hando/dispatch.go:77-80`, unchanged by this phase — only the WRAPPER's *reaction* to that stderr/exit is new).
- Start-object timing: the process invoked as `local --jsonl ...` (whether run directly or spawned by ssh) must print `start` right after parse/validate/version-check, BEFORE preflight/bridge-connect. "Process ended before its start line" (ssh failure, binary not found, usage error, version mismatch) = exit 3 nothing ran; a bridge-miss or preflight failure arrives as `abort` AFTER `start` = exit 4; connection lost after `start` with no `done`/`abort` = exit 5 `state=unknown`. Wrapper kills ssh at `--timeout` + 5s.
- `abort` relay: `{"event":"abort","code":"E_...","msg":"..."}`; exit mapping E_VALIDATE→2, E_CONNECT→3, else→4 (already implemented generically in `internal/output/codes.go:44-53` — reuse, do not reimplement).
- `[f]` payloads resolved on the agent's (initiating) machine: txt[f]/paste[f]/clip[f] → txt[]/paste[]/clip[] with file contents inlined in TEXT ESCAPES form; `qclip[f]<path>` → `qclip[]`, result written to local `<path>` afterward. The rewritten line is re-validated against the 64 KiB line limit (E_VALIDATE, exit 2, nothing sent) using the ORIGINAL `op.Src` as the diagnostic's source text.
- Captures cross the wire as `"fmt":"png"` only; local side writes `.png` files under the same `<out>/<NNNN>-<label>-<UTC ts>.png` convention `local` already uses.
- Byte-identical-output constraint: only three things differ from a real local run — capture/qclip local paths, the `start` object's `out`/`dest`, and err results' `src` (restored from the local parse by line number so an inlined `[f]` line shows as written).
- Phase 1's own verification boundary (ticket text, authoritative): an integration test using a fake `ssh` executable on PATH that runs a gotto-hando test binary built with a new `dryrun` build tag (never selectable in a release build), covering: EXAMPLES-section byte-identical stdout vs. a local dry-run (capture paths included); a failing inlined `paste[f]` line reporting `paste[f]./cmd.py` as its source; `--request-perms` forwarded to a fake windows remote → `start`, `abort E_VALIDATE`, local exit 2; `txt[f]`/`qclip[f]` round-trip; a `txt[f]` file whose escaped form exceeds 64 KiB → exit 2, no ssh spawn; exit 3 on connect failure / missing remote binary / version mismatch / pre-`--expect-version` usage error; exit 4 on `abort` (E_SESSION example) with nothing on stdout / `abort: ... (E_CODE)` on stderr (plain) or the abort object verbatim (`--jsonl`); exit 3 on `abort E_CONNECT`; exit 5 `state=unknown` on mid-run ssh kill; held-key release on remote stdout EOF through the dry-run backend.

## Codebase Findings

- `cmd/gotto-hando/dispatch.go:159` — the catch-all `return abort(output.EValidate, "remote destinations not implemented")` for every `dest != "local"`; this is the seam Phase 1 replaces with the real ssh transport call.
- `cmd/gotto-hando/dispatch.go:77-80` — `--expect-version` mismatch check already runs before any line parsing, matching "nothing else printed"; do not reorder.
- `cmd/gotto-hando/dispatch.go:99-101,116-157` — the `opts.RequestPerms` branch and the `dest=="local"` branch. Today, `WriteStart` is issued only AFTER `engine.Run` fully returns (all results already computed in memory, `sum.Results` looped afterward) — there is no early, flushed `start` line before `Preflight`. Since the ssh-spawned remote is literally this same `local --jsonl ...` code path, and the wrapper must be able to distinguish "process died before start" (exit 3) from "aborted after start" (exit 4) or "connection lost after start" (exit 5), this path needs restructuring: print `output.WriteStart` immediately after `parseAndValidate` succeeds when `opts.JSONL`, wire `engine.RunOptions.OnResult` to stream each result via `output.WriteResult` as it's computed, and use `output.WriteAbortEvent` (not the full `abort()`/`WriteAbort`) on a subsequent `sum.Aborted` so `start` is never double-printed. Plain mode must NOT gain an early "out" line — `output.WriteAbort`'s existing split (next finding) already differentiates jsonl-always-prints-start-then-abort vs. plain-never-prints-on-abort, so this refactor is byte-identical for direct `local` runs (only internal timing changes) and is required for the remote case.
- `internal/output/writer.go:150-198` — `WriteStart` / `WriteAbort` / `WriteAbortEvent` already split exactly for this "print start once, then abort separately" reuse (doc comment explicitly names the bridge forwarder as the precedent); reuse directly, no new formatting code needed.
- `internal/engine/run.go:36-51,99-113` — `RunOptions.OnResult` (built in Phase 0 for the bridge) already streams every `Result` synchronously, including skip/warn/cap-on-error branches, with the documented invariant "every `Results` append has a matching `OnResult` call." `Run`'s first action is `be.Preflight(ctx, seq)`. Reuse this mechanism for the local/remote-shared dispatch path instead of building a second one.
- `cmd/gotto-hando/dispatch_windows.go:265-439` (`forwardToBridge`, `relayResult`, `relayDone`, `decodeAbortEvent`, `decodeDoneEvent`) — closest existing precedent for "wait for a start line, relay per-line JSONL objects in the caller's chosen format via `engine.ResultDetailFromJSON`, map abort codes to exit, verbatim-passthrough in `--jsonl`." The new ssh relay loop should follow this shape, generalized: source is an `os/exec.Cmd`'s stdout pipe instead of a bridge connection, and a `perms` terminal event (not just `done`) must be handled for `--request-perms`.
- `internal/engine/wire_result.go:31` (`ResultDetailFromJSON`, package `engine`, no build tag, GOOS-agnostic) — already reconstructs plain `Detail`/`Extra`/`AlwaysShow` from a decoded JSONL fields map; reuse directly as `dispatch_windows.go` already does.
- `internal/engine/capture.go:23` (`captureTimestampLayout`), `:49-63` (`capturePath`), `:80-86` (`writeCaptureFile`) — all unexported; they implement exactly the `<out>/<NNNN>-<label>-<UTC ts>.png` naming/writing convention the wrapper must reproduce when decoding `--inline-captures` base64 data locally. Export them (rename only, e.g. `CapturePath`/`WriteCaptureFile`/`CaptureTimestampLayout`) instead of duplicating the logic — the wrapper keeps its own per-run sequence counter (mirrors `engineState.capSeq`, one increment per `cap` result line, not per frame).
- `internal/syntax/escape.go:14-51` (`applyEscapes`, decode-only, unexported) — no encode/escape-back function exists anywhere in the repo. New code is required: a small escaper that only needs to handle `\` → `\\`, LF → `\n`, TAB → `\t` (everything else, including non-ASCII, passes through literally, since `applyEscapes` only special-cases those three plus `\uXXXX` on decode) to keep the round trip exact.
- `internal/syntax/inline.go:20-58` (`Inline`) — already reads local `[f]` files into `op.Text`/`op.HasText` for txt/paste/clip at parse time, for BOTH local and (going forward) remote dispatch, since `parseAndValidate` (`cmd/gotto-hando/analyze.go:17-29`) is dest-agnostic. The wrapper's line-rewrite step operates on the already-inlined `op.Text` — it must not re-read files itself.
- `internal/ir/validate.go:29-34` — `Validate()` only checks `len(op.Src) > MaxLineBytes` (the raw, pre-inline source line); it never sees the post-inline/escaped length. The ticket's "rewritten line re-validated against 64 KiB" requirement is therefore new wrapper-only logic (construct the outgoing line text, check its byte length against `ir.MaxLineBytes`, diagnostic uses the ORIGINAL `op.Src`) — not a change to `ir.Validate`.
- `internal/syntax/build.go:51-58` (txt/paste/clip `[f]`), `:280-283` and comment at `:369-370` — `op.FromFile`/`op.FilePath` are already fully parsed for `qclip[f]<path>` too; `FilePath` is explicitly documented as local-only, never serialized to wire IR (`internal/ir/ops.go:140-146`). Confirmed via `grep`: `internal/engine/query.go`'s `KindQueryClip` case never reads `FromFile`/`FilePath` — direct-`local` `qclip[f]` file-writing is unimplemented today (pre-existing gap, see Out of Scope).
- `internal/output/codes.go:14-53` — `ErrorCode` consts, `AbortExit()` (E_VALIDATE→2, E_CONNECT→3, else→4), and `ExitStateUnknown = 5` already exist exactly per the ticket; reuse directly.

## Implementation Plan

1. `cmd/gotto-hando/dispatch.go` — restructure the `dest=="local"` branch (`:116-157`): after `parseAndValidate` succeeds, when `opts.JSONL`, call `output.WriteStart` immediately (before `shouldForwardToBridge`/`newLocalBackend`/`engine.Run`); pass `engine.RunOptions.OnResult` writing each result via `output.WriteResult` as it arrives; on a subsequent `sum.Aborted`, call `output.WriteAbortEvent` (plain mode keeps its current fully-buffered, no-early-"out"-line behavior via `abort()` unchanged). Replace the `dest != "local"` fallthrough (`:159`) with a call into the new remote package (step 3). Route the `opts.RequestPerms` branch (`:99-101`) to the same new package when `opts.Dest != "local"`.
2. `internal/engine/capture.go` — export `capturePath`→`CapturePath`, `writeCaptureFile`→`WriteCaptureFile`, `captureTimestampLayout`→`CaptureTimestampLayout` (rename only); update the same file's internal call sites.
3. New package `internal/remote` (GOOS-agnostic, no build tag) — pure/testable logic:
   - Forwarded-arg builder per the OPTIONS forwarding table (`--jsonl --inline-captures --expect-version <ver>` always; `-q/--delay/--timeout/-k/--cap-on-error/--request-perms` when given; never `--out`/`--remote-bin`).
   - Line rewriter: given the original `lines []string` and the parsed `*ir.Sequence`, for each op with `FromFile` and `Kind` in {text, clipboard, paste}, rebuild the line as `<cmd>[<mods minus f>]<escaped op.Text>` via a new escape encoder (`\`→`\\`, LF→`\n`, TAB→`\t`, else literal); for `qclip[f]<path>`, rebuild as `qclip[]` and record `{Line, FilePath}` for write-back; every other line passes through verbatim. Re-check each rewritten line's byte length against `ir.MaxLineBytes`; on violation return an `ir.Diagnostic` keyed on the ORIGINAL `op.Src`.
   - JSONL relay decoders: `start`/`abort`/`perms`/`done`/per-line-object detectors (mirror `decodeAbortEvent`/`decodeDoneEvent` from `dispatch_windows.go`, add `decodePermsEvent`).
   - Local per-line rewrite: capture (`"data"`/`"fmt"` → base64-decode → `engine.WriteCaptureFile(engine.CapturePath(...))` with a wrapper-local counter), qclip write-back (`"text"` → write to the recorded `FilePath`), err `src` restoration (replace the wire `src` with the local `op.Src` for that line number, via a `map[int]string` built off the local `seq`).
   - `done` synthesis for connection loss: accumulate ok/err/skip from every per-line object actually relayed, `held_released=0`, `elapsed_ms` = wall time since local start, `state=unknown`.
4. New file `cmd/gotto-hando/remote.go` (GOOS-agnostic, no build tag) — CLI glue:
   - `runRemote(ctx, opts, seq, lines, stdout, stderr, abort) int`: build ssh argv via step 3's arg builder; `exec.CommandContext` with a deadline = parsed `--timeout` (default 300s via `syntax.ParseDurationMS`, mirroring `dispatch_windows.go:157-161`) + 5s; `cmd.Stderr = stderr` direct passthrough (so ssh's own diagnostics and the remote's pre-start stderr — including `version mismatch: ...` and usage errors — reach the caller verbatim); `cmd.Stdin` fed the rewritten sequence text (closed immediately for `--request-perms`, no sequence); `cmd.Stdout` read via `bufio.Scanner`.
   - Read loop: first line must decode as `start`; if the process/ssh exits or EOF's first, `abort(EConnect, ...)` → exit 3, nothing else printed. Once seen, print the wrapper's own `output.WriteStart` (local `dest`/`outDir`) immediately, then loop: `abort` → `output.WriteAbortEvent` + `AbortExit`; per-line object → apply step 3's local rewrites, print via `output.WriteResult` or verbatim passthrough in `--jsonl` (mirroring `relayResult`); `done` → `output.WriteDone`, exit per `Done.Err>0`; scanner ending without `done`/`abort` after `start` (or the +5s kill firing) → step 3's synthesized `done` with `state=unknown`, exit 5.
   - `runRemoteRequestPerms(...)`: same spawn/start-wait shape, no stdin sequence, terminal event is `perms` (print the `perms=` line / object, exit 0 when both ok else 4) instead of `done`.
5. `internal/backend/dryrun/dryrun.go:1-6` — update the doc comment to note the `dryrun`-build-tag exception.
6. `cmd/gotto-hando/dispatch_darwin.go:1`, `dispatch_other.go:1`, `dispatch_windows.go:1` — change each `//go:build` line to add `&& !dryrun`.
7. New file `cmd/gotto-hando/dispatch_dryrun.go` (`//go:build dryrun`) — `newLocalBackend` returns `&dryrun.Backend{}`; `requestPerms` mirrors `dispatch_other.go`'s `"--request-perms is macOS only"` stub (this is what makes the "fake remote reporting os=windows" verification bullet pass); `runBridge`/`shouldForwardToBridge`/`forwardToBridge` mirror `dispatch_other.go`'s stubs (dry-run bridge routing is Phase 2, out of scope here).
8. `cmd/gotto-hando/main_test.go` — remove the `"remote-dest"` case from `TestNotImplementedOptionsExitTwo` (`:163-186`); change `TestExpectVersionMatch` (`:256-262`) to pass an explicit `"local"` dest.
9. New test file(s) under `cmd/gotto-hando/` (e.g. `remote_test.go` + `testdata/fakessh/main.go`) — a `TestMain`-style setup building the `dryrun`-tagged gotto-hando binary and a fake `ssh` Go program once, both on a temp `PATH`, driving the EXISTING real `binPath` binary (already built by `main_test.go`'s `TestMain`) against `<dest>` invocations; cover every scenario in the ticket's Phase 1 verification list (see Relevant Ticket Contract).
